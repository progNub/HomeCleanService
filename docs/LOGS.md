# Logs and authenticated Dozzle access

Use `make prod-logs` or `make prod-logs-web` for diagnostics. Docker logs rotate
by size. Notification errors omit Telegram payloads and raw responses, but access
logs and other container output may still contain sensitive information: limit
access and avoid sharing unredacted downloads.

Open https://logs.homecleanservice.by and sign in with your existing Dozzle
credentials. Nginx proxies HTTPS to Dozzle with buffering disabled for live logs.
File-based authentication is mandatory; container actions and shell access are
disabled. No users/default passwords are generated by application startup.

Dozzle uses the `tools` Compose profile. Regular releases start/update it only
when deploy/dozzle/users.yml exists and verify the login page and anonymous
stream rejection. Without this file, configure credentials and run make prod-tools.
Nginx resolves Dozzle dynamically: an unavailable log viewer does not prevent
the main site from starting (the logs endpoint returns 502 until Dozzle is ready).
Port 8081 is bound only to loopback, never directly to the public interface.

## Create credentials explicitly

Generate `deploy/dozzle/users.yml` with a unique password:

```bash
read -rsp 'Dozzle password: ' DOZZLE_PASS
export DOZZLE_PASS
DOZZLE_USER=operator make dozzle-gen-pass
unset DOZZLE_PASS
```

DOZZLE_USER defaults to admin; DOZZLE_PASS has no default and the literal password
admin is rejected. Optional DOZZLE_EMAIL and DOZZLE_NAME customize the account.
The generator replaces users.yml, so preserve existing entries before using it
on a multi-user setup. It writes a password hash with file mode 0600; Git ignores
the file. Interactive input avoids shell history, but generation passes the
password to a local Docker process, so run it on a trusted host.

For production, with the image configured in .env or exported:

```bash
make prod-tools
```

For development:

```bash
docker compose -p homeservice-dev -f deploy/docker-compose.yml -f deploy/docker-compose.dev.yml --profile tools up -d dozzle
```

Restart only Dozzle after changing credentials:

```bash
docker compose --env-file .env -p homeservice-prod -f deploy/docker-compose.yml -f deploy/docker-compose.prod.yml restart dozzle
```

## Optional access over SSH

From your workstation:

```bash
ssh -N -L 8081:127.0.0.1:8081 DEPLOY_USER@SERVER
```

Open [localhost:8081](http://localhost:8081) and sign in. Development on the same
machine needs no tunnel. If port 8081 is occupied, use -L 18081:127.0.0.1:8081 and
open local port 18081 instead.

The socket mount is read-only at the filesystem level; that does not make the
Docker API intrinsically read-only. Treat Dozzle/credentials as privileged access.
Do not publish its port or re-enable actions/shell access. Use a strong unique
password. For connection problems, verify container status, the users file,
Nginx configuration and `make prod-logs-dozzle`. Run
`bash deploy/scripts/logs-smoke.sh` to check HTTPS login and anonymous API denial.
